# 연차 계산 방식과 관리자 조정 매뉴얼

> 대상: 연차 계산 규칙을 고치거나 확인하는 개발자·코딩 에이전트
> 결정: 2026-11-10 사용자 결정, **2026-11-12 변경**(입사 다음 해부터 15일 계열 - 남은 월 단위·비례 부여 삭제, 12월에 다음 해 행 미리 생성) (근거 논의는 [features.md 7.4](features.md))
> 상태: **구현 완료(백엔드, 2026-11-12)**. 구현 구조는 [docs/backend/leaves.md](../backend/leaves.md).
> 계산 규칙을 바꾸면 이 문서 → 계산 함수 → 단위 테스트 예시표 순서로 함께 고친다.

---

## 1. 한눈에 보기

```text
부여 일수 = baseDays(규칙 계산, 배치가 갱신) + permanentDays(영구 조정, 매년 복사) + adjustDays(매년 초기화되는 조정)   ← 25일 한도 없음
사용 일수 = 그 연도에 최종 승인(APPROVED)된 연차(ANNUAL) LeaveRequest.days 합계   ← 저장하지 않음
진행 중   = 그 연도의 결재 진행 중(REQUESTED·IN_PROGRESS) 연차 LeaveRequest.days 합계 ← 저장하지 않음
잔여      = 부여 − 사용 − 진행 중
미사용    = 부여 − 사용   (연도가 끝난 뒤 연차수당 근거, 조회 시 계산)
```

- 기준 기간: **회계연도(1/1~12/31, KST)**. 연도를 걸치는 휴가는 나눠 신청한다(한 신청은 한 연도 안).
- 차감 대상: **연차(`ANNUAL`)만**. 병가(`SICK`)·공가(`OFFICIAL`)는 결재만 거치고 잔여와 무관하다.
- 이월: **자동 이월 없음**. 필요하면 관리자가 새해 `adjustDays`로 넣는다(사유: 이월).

## 2. 저장 구조 (`LeaveGrant`, 구현 시 추가)

| 컬럼 | 의미 |
|---|---|
| `userId`, `year` | 회원·회계연도. `@@unique([userId, year])` |
| `baseDays` `Decimal(5,2)` | 규칙 계산값. **배치·재계산만** 쓴다 |
| `permanentDays` `Decimal(5,2)` | 그해에 적용된 **영구 조정값**(회원 설정 `LeaveUserSetting.permanentDays`를 재계산·저장 때 복사, 입사한 해는 0). 연도마다 저장해 영구값을 바꿔도 지난 연도 기록은 그대로 (2026-11-12) |
| `adjustDays` `Decimal(5,2)` | **매년 초기화되는 조정값**(음수 가능, 0.25 단위). 새해 행은 0. **배치는 절대 건드리지 않는다** |
| `adjustReason` | 조정 사유 |

- 계산값과 조정값을 나눈 이유: 규칙대로 다시 계산해도 관리자 조정이 지워지지 않게 하기 위함.
- 영구 조정(2026-11-12 사용자 결정): 임원 전입 등 다른 근속을 인정할 때 매년 조정을 다시 넣지 않도록 회원별 `LeaveUserSetting(permanentDays, permanentReason)`을 둔다. 근속 가산이 2년마다 1일이라 인정 근속이 짝수 년이면 "+일수"가 근속 인정과 매년 같다(홀수 년은 해마다 1일 차이가 날 수 있어 매년 조정값으로 맞춘다). 입사한 해의 월 단위 연차는 영구 조정 대상이 아니다(매년 조정값으로만).
- 사용 일수를 저장하지 않는 이유: 저장값과 승인 내역이 어긋날 일을 없애기 위함.
- 연도별 행은 지우지 않는다(지난 연도 기록 = 연차수당 근거).

## 3. baseDays 계산 규칙

### 3.1 법 근거 (근로기준법 제60조)

| 조항 | 내용 | 이 시스템에서 |
|---|---|---|
| 제1항 | 1년간 80% 이상 출근 시 15일 | 1년 이상 근속자 기본 15일 (출근율은 보지 않음) |
| 제2항 | 1년 미만 또는 80% 미만 출근자는 1개월 개근 시 1일 | **입사한 해에만** 한 달마다 1일(그해 안에 생기는 만큼, 최대 11일). 개근 여부는 보지 않음 |
| 제4항 | 3년 이상 계속 근로 시 최초 1년을 초과하는 계속 근로 연수 2년마다 1일 가산, 합계 한도 25일 | `15 + floor((n−1)/2)`, 최대 25 |

> 법 원칙은 입사일 기준이다. 회계연도 기준은 실무에서 쓰는 방식이며, 퇴직 시 입사일 기준보다 불리하면 차이를 정산해야 한다는 해석이 있다. 퇴직 정산 계산은 범위 밖이다.
> 2026-11-12 변경(사용자 결정): 입사 다음 해 1/1에 15일을 모두 준다. 대신 다음 해에 입사 1주년 전까지 생길 월 단위 연차는 따로 주지 않는다. 이전 안(남은 월 단위 + 비례 부여)보다 다음 해 부여 일수는 항상 같거나 많다(예: 7/1 입사 13.75 → 15, 12/31 입사 11.25 → 15). 규칙이 단순하고 12월에 다음 해 값을 미리 확정할 수 있다.

### 3.2 입력

- `joinAt`: `Users.joinAt` (입사일, KST 날짜)
- `year`: 계산할 회계연도 Y
- `asOf`: 기준일 (배치 실행일 또는 "지금 재계산"을 누른 날, KST 날짜). 입사한 해의 월 단위 연차가 `asOf`까지 생긴 만큼만 들어간다. 다음 해부터는 `asOf`와 무관하다.
- J = `joinAt`의 연도

### 3.3 규칙

| 연도 | baseDays |
|---|---|
| Y < J | 행을 만들지 않는다 |
| Y = J (입사한 해) | **월 단위** |
| Y ≥ J+1 | n = Y − J, `min(25, 15 + floor((n−1)/2))` (n = 1, 2 → 15, n = 3 → 16 …) |

**월 단위**: k = 1 … 11에 대해 `월차일_k = joinAt + k개월`이라 할 때, `월차일_k`가 입사한 해(J) 안에 있고 `≤ asOf`인 k의 개수.

- `+k개월`은 말일 보정한다(1/31 입사 → 2/28(윤년 2/29), 3/31, 4/30 …). date-fns `addMonths`와 같은 동작.
- 다음 해(J+1)로 넘어가는 월차일은 세지 않는다. 다음 해 1/1에 15일을 주기 때문이다(2026-11-12 사용자 결정).
- 이전 안(2026-11-10)의 "다음 해 = 남은 월 단위 + 비례 부여(`15 × 작년 근무일 / 365`, 0.25 단위 올림)"는 삭제했다. 기록은 devlog·changelog.

### 3.4 예시 (단위 테스트 기준표로 그대로 쓴다)

`asOf`는 그 연도 12/31(1년 전체가 지난 뒤) 기준이다.

| 입사일 | 연도 | 월 단위 | 15일 계열 | baseDays | 설명 |
|---|---|---|---|---|---|
| 2026-07-01 | 2026 | 5 (8/1~12/1) | - | 5 | 입사한 해 |
| 2026-07-01 | 2027 | - | 15 (n=1) | 15 | 다음 해 1/1에 15일 |
| 2026-07-01 | 2028 | - | 15 (n=2) | 15 | |
| 2026-07-01 | 2029 | - | 16 (n=3) | 16 | 3년차 첫 가산 |
| 2026-07-01 | 2031 | - | 17 (n=5) | 17 | |
| 2026-01-01 | 2026 | 11 (2/1~12/1) | - | 11 | |
| 2026-01-01 | 2027 | - | 15 (n=1) | 15 | |
| 2026-12-31 | 2026 | 0 | - | 0 | 첫 월차일 2027-01-31은 다음 해라 세지 않음 |
| 2026-12-31 | 2027 | - | 15 (n=1) | 15 | |
| 2026-01-31 | 2026 | 11 (2/28, 3/31, … 12/31) | - | 11 | 말일 보정 |
| 2006-03-01 | 2026 | - | 24 (n=20) | 24 | 15+floor(19/2)=24 |
| 2005-03-01 | 2026 | - | 25 (n=21: 15+10) | 25 | 한도 |
| 2000-03-01 | 2026 | - | 25 (n=26 → 27, 한도 25) | 25 | 한도 |

연도 중간 `asOf` 예: 2026-07-01 입사, Y=2026, `asOf` = 2026-10-01(배치 실행일) → 월차일 8/1·9/1·10/1 → **3**.

### 3.5 계산 대상이 아닌 경우

- `joinAt`이 없는 회원(가입 승인 전, `GUEST`)은 행을 만들지 않는다. 승인된 회원은 입사일을 비울 수 없다(features.md 5.1).
- `joinAt > asOf`(입사 예정)는 0이다. 행을 만들지 않아도 된다.
- 삭제된 회원과 퇴사(`RESIGNED`) 회원은 배치가 갱신하지 않는다. 퇴사 시점의 행이 그대로 남는다.
- 휴직(`INACTIVE`) 회원은 **포함**한다(재직자 전원, 2026-11-12 결정). 휴직 기간 차감이 필요하면 관리자 조정으로 넣는다.

## 4. 배치와 재계산

- **매월 1일 00:00(KST)** 실행(2026-11-12 시각 유지 결정). 대상 회원의 **올해** 행을 upsert하고 `baseDays`만 갱신한다(`asOf` = 실행일).
  - **12월(12/1 배치, 12월 중 "지금 재계산")에는 다음 해 행도 만든다**(2026-11-12 사용자 결정). 다음 해 1월 휴가를 12월에 미리 신청할 수 있게 하기 위함이다. 다음 해 값은 `asOf`와 무관해 1/1 배치가 같은 값으로 다시 계산하고, 그사이 넣은 조정값은 유지된다. 12월에 아직 입사 전인 회원(입사 예정)은 만들지 않는다.
  - 1/1 한 번만 돌리지 않는 이유: 입사한 해의 월 단위 연차가 매달 늘고, 연도 중 입사자는 그해 행이 없기 때문.
  - 실행이 한 번 빠져도(서버 중단) 다음 실행에서 맞춰진다(멱등).
- 관리자 화면 **"지금 재계산"**: 배치와 같은 서비스를 오늘 날짜로 호출한다. 신규 입사자·입사일 변경을 바로 반영할 때 쓴다(관리자 회원 상세에서 입사일을 바꾸면 안내 창에 버튼이 있다).
- **올해 행(12월에는 다음 해 행도)만** 갱신한다. 지난 연도 행은 배치·재계산·관리자 조정 모두 바꿀 수 없다.
- 스케줄러는 `@nestjs/schedule`(구현 시 도입). 휴가 옵션이 꺼져 있으면 모듈이 등록되지 않으므로 배치도 돌지 않는다.

## 5. 관리자 조정 방법

계산이 틀렸거나 회사 규정(이월, 포상 휴가, 별도 부여, 개근 미달 차감 등)을 반영해야 할 때 쓴다.

1. 연차 관리 화면에서 회원의 **올해** 행의 [조정]을 누른다(12월에는 다음 해 행도 - 이월 등, API `year`). 계산값·영구 조정·올해 조정·부여·사용·진행 중·잔여가 보인다.
2. 조정 창에서 **영구 조정값·영구 조정 사유**와 **매년 초기화되는 조정값·그해 조정 사유**를 입력해 저장한다(±, 0.25 단위, 값이 0이 아니면 사유 필수).
   - 영구 조정값: 저장하는 즉시 올해와 (있으면) 내년 행에 반영하고, 이후 재계산이 매년 복사한다. 입사한 해 행·지난 연도 행은 바뀌지 않는다. 예: 계열사 근속 10년 인정 → +5
   - 매년 조정값은 누적 입력이 아니라 **그 연도의 조정 총합**이다. 예: 이월 +3을 넣은 뒤 포상 +1을 더하면 조정값을 4로 바꾸고 사유를 "이월 3, 포상 1"로 고친다.
   - 차감도 음수로 넣는다(예: −1, 사유 "개근 미달 1개월").
3. 저장하면 감사 로그(`AuditTargetType.LEAVE`)에 변경 전·후 값과 사유가 남는다. 조정 이력은 감사 로그로 확인한다.
4. 이후 배치가 `baseDays`를 다시 계산해도 조정값은 그대로 유지된다.

규칙 자체가 틀린 경우(모든 회원에게 해당)에는 조정하지 말고 **계산 함수를 고친 뒤 "지금 재계산"**을 실행한다. 올해 행만 다시 계산되고 지난 연도는 바뀌지 않는다.

## 6. 신청·승인 시 확인 (참고)

- 상신 시: `사용 + 진행 중 + 이번 신청 ≤ 부여`. 회원 단위 잠금(`SELECT ... FOR UPDATE`) 안에서 확인해 같은 회원의 동시 상신을 막는다.
- 최종 승인 처리기(결재가 넘겨준 같은 `tx`)에서 한 번 더 확인한다. 부족하면 예외 → 승인 전체 롤백.
- 그 연도 `LeaveGrant` 행이 없으면 부여 0으로 본다(신청 불가). 이때 안내 문구는 "관리자에게 문의"로 한다.
