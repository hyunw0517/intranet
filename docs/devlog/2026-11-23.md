  - 대신하는 것 (Claude 제안): 데모가 안정된 뒤 추가할 **친구용 인트라넷 인스턴스**가 같은 역량을 보여 준다. EC2 하나에 서비스 여러 개(`intranet-*` 두 벌), Nginx 서브도메인 라우팅(`intranet.`/`friends.`), RDS 하나에 DB 여러 개 + 계정 분리(`intranet`/`intranet_friends`). 게다가 "이미지에 인스턴스별 값을 넣지 않고 환경변수·DB만 바꿔 두 벌 운영"이라는 이미지 설계 이유를 직접 보여 준다.
  - 결과: 운영 RDS(PostgreSQL 18)에는 `intranet` DB만 둔다. SNS는 로컬(PostgreSQL 17)과 GitHub 저장소로 남기고, 필요해지면 같은 EC2·RDS에 서비스만 추가하면 된다. 예상 서비스는 `intranet-backend`, `intranet-frontend`, `nginx`.
  - 문서: AGENTS.md v1.97(1·3·16장), [changelog.md](../design/changelog.md), [deploy.md](../design/deploy.md) 1·2·4장. SNS 관련 기록은 지우지 않고 "보류"로 남겼다.

## 2026-11-27 · trust proxy · 로그인 IP 요청 한도 10 → 200 · v1.0.0 이미지 GHCR 공개 · AWS 계정 설정 판단

관련 커밋: `7aa6a1c` (git 태그 `v1.0.0`) · 같은 날 다른 세션 커밋 `c455249`(배포 예상 비용, [deploy.md](../design/deploy.md) 5장)는 이 일지에 별도 항목이 없다

- **`trust proxy` = 1 (사용자 결정 A, Claude 구현)**: nginx 뒤에서는 백엔드가 직접 연결을 받는 상대가 항상 nginx라 `req.ip`가 모두 nginx 컨테이너 주소가 된다. 그러면 ① 로그인·가입 IP 요청 수 제한(`ThrottlerGuard`, 기본 추적 값이 `req.ip`)을 전 회원이 한 묶음으로 나눠 쓰고 ② 감사 로그 IP(`RequestContext`가 저장한 요청의 `req.ip`)가 전부 nginx 주소로 남는다. nginx는 이미 `X-Forwarded-For`를 넘기고 있었고, 백엔드가 그 값을 믿지 않는 것이 문제였다.
  - 선택지: A 바로 앞 프록시 한 단계만 믿기(`app.set('trust proxy', 1)`) / B nginx 컨테이너 IP 대역만 믿기. A를 고른 이유: 백엔드 포트를 외부에 열지 않아(운영 compose) nginx만 접근할 수 있고, B는 Docker 네트워크 대역이 바뀌면 같이 고쳐야 한다.
  - 1단계만 믿으므로 사용자가 헤더 앞쪽에 넣은 가짜 주소는 쓰이지 않고, nginx가 붙인 마지막 주소(실제 접속 주소)가 `req.ip`가 된다. [main.ts](../../backend/src/main.ts)에만 두어 e2e(프록시 없음)에는 영향이 없다.
  - 11/09 설계 때 "배포 시 Nginx 주소로 한정"으로 적었던 것을 이번에 단순한 쪽(1단계)으로 정했다([audit-notifications.md](../backend/audit-notifications.md) 50행 갱신).
- **로그인 IP 한도를 1분 10회 → 200회로 (사용자 지적·결정) ⭐**: trust proxy 설명 중 사용자가 "기존 설계도 같은 회사 IP로 10명이 1분 안에 로그인하면 막히지 않나"를 짚었다. 맞다 - 회사 PC는 NAT로 공인 IP 하나를 함께 쓰고, `ThrottlerGuard`는 **성공한 로그인도 센다**. 공격이 없어도 출근 시간에 1분 동안 회사 전체가 429를 받을 수 있다(계정 잠금은 사번 기준이라 번지지 않음).

  - 근본 해결은 이미 계획된 기준 변경(IP+사번 빡빡하게 + IP 느슨하게, 메모리 방식)이다. 11/23 Redis 작업을 빼면서 그 자리에 넣어 둔 것을 이번에 다시 확인했다.
  - "PC(클라이언트) 단위로 셀 수 있나"도 검토: 쿠키·기기 ID는 클라이언트가 보내는 값이라 공격자가 지우거나 바꾸면 그만이고, 브라우저 지문은 부정확하고 개인정보 문제가 있다. TCP 연결에서 나오는 IP가 그나마 바꾸기 어려운 값이라 IP 기준을 유지했다.
