> 작성일: 2026-11-10
> 업무 규칙은 [features.md 7.5](../design/features.md), 백엔드 구조·API는 [backend/approvals.md](../backend/approvals.md).

## 1. 화면과 경로

| 경로 | 화면 | 누가 |

| `/approvals` | 결재함: 결재 대기 / 결재 예정 / 기안함 / 임시저장 / 결재 완료 / (관리자) 전체 문서, 상태 필터, [새 문서] | 직원 |

| `/approvals/[id]` | 상세 (**알림의 이동 주소**): 결재선 칸, 권한별 버튼, 본문, 첨부, 처리 이력 | 기안자·결재라인·관리자 |

- 결재함의 결재함·상태·페이지는 URL(`?box=&status=&page=`) → 상세에서 뒤로 가기·새로고침해도 유지
- 탭 건수(결재 대기·결재 예정·기안함·임시저장, 0건은 숨김): `useApprovalCounts` → `GET /approvals/documents/counts`. 기안함은 결재요청·결재중만 센다(사용자 결정). `approvalKeys.counts()`가 `all` 아래라 상신·승인 후 자동으로 다시 조회된다

## 3. 버튼은 서버가 준 권한으로만

상세 응답의 `permissions`(`canEdit` / `canCancel` / `canApprove` / `canCopy` / `canReplaceApprover`)만 보고 버튼을 그린다. 화면이 상태·기안자·차례를 다시 계산하지 않아 규칙이 한 곳(서버)에만 있다.

| 권한 | 버튼 |
|---|---|
| `canEdit` (기안자, 임시저장) | 삭제 · 수정 · 상신 |
| `canCancel` (기안자, 결재요청) | 회수 |
| `canApprove` (내 차례) | 반려(의견 필수) · 승인(의견 선택) |
| `canCopy` (기안자, 반려·회수) | 다시 기안 → 새 임시저장의 수정 화면으로 |
| `canReplaceApprover` (관리자, 진행 중) | 남은 단계마다 "결재자 교체" |

- **409 처리**: 동시 처리로 상태가 이미 바뀐 경우(두 탭·회수와 승인 겹침) 서버 메시지를 띄우고 상세를 다시 조회해 버튼을 맞춘다.
- 남은 단계의 `approverUsable: false`(퇴사·휴직·삭제)는 "결재할 수 없는 결재자" 경고로 표시 → 관리자 교체 안내.

## 4. 저장 → 상신 (API가 나뉘어 있음)

```text
[상신] → createApprovalDocument (임시저장) → submitApprovalDocument → 상세로 이동
              └ 상신만 실패(예: 그사이 결재자 퇴사 400) → 문서는 임시저장으로 남음 → 수정 화면으로 보내고 오류 안내
[임시저장] → create/update만 → 상세로 이동
```

- 임시저장은 제목만 필수, 상신은 결재자 1명 이상 (서버와 같은 기준)
- 결재라인 불러오기: 지정할 수 없는 결재자(`usable: false`)와 기안자 본인은 빼고 채우고, 뺀 인원을 알림. 불러온 뒤 자유롭게 고칠 수 있고 템플릿 id는 기록만.

## 5. 처리 이력 표시

서버는 변경 전·후 상태만 저장한다. 중간 승인은 `결재중 → 결재중`, 결재자 교체는 같은 상태라 상태 이름만 보여 주면 알아볼 수 없어서, 화면에서 동작 이름(상신 · 승인 · 최종 승인 · 반려 · 회수 · 결재자 변경)으로 바꿔 보여 준다(`historyAction`).
- 작성(임시저장 생성) 행은 표시하지 않는다 - 상신 이력으로 충분 (2026-11-10 사용자 결정). 서버에는 그대로 저장된다.

## 7-1. 병렬 단계 (2026-11-10 추가)

- 한 단계에 여러 명 = 병렬(모두 승인해야 다음 단계, 한 명 반려 = 문서 반려). 서버는 같은 `stepOrder` 행들로 저장하고, 화면은 `groupStepRows`로 단계 카드로 묶는다.
- 작성: [단계 추가]로 새 단계, 단계 안의 [이 단계에 결재자 추가 (병렬)]로 같은 단계에 추가. 마지막 사람을 빼면 단계도 없어진다. 템플릿을 불러올 때도 묶음 유지(뺀 결재자 때문에 빈 단계는 없앰)
- 상세: 단계 제목에 "병렬 (모두 승인해야 다음 단계)", 지금 단계는 "지금 차례", 결재 차례인 사람 카드만 강조. 결재함 목록의 "현재"는 지금 단계의 남은 결재자(여러 명이면 쉼표)
- 결재자 교체는 카드마다(단계 행 id)
- 브라우저 확인: 작성(병렬 2 + 1) → 상신 시 두 명 모두 결재 차례 → 한 명 승인 후 같은 단계 유지 → 관리자가 2단계 결재자 교체(**화면 조작 확인**) → 두 번째 승인 후 교체된 결재자 차례·목록 "결재 2/3 · 현재 신지민", 병렬 결재라인 저장("김태윤, 오도윤 (합의) → 정서윤") → 불러오기 시 묶음 유지, 390px 넘침 없음, 콘솔 오류 없음

- 부서 결재라인 추가의 부서 선택지는 맡은 부서 + 하위 부서 전체를 "기술본부 › 개발1팀"처럼 경로로 보여 준다(`departments[].path`). 브라우저 확인: 기술본부 관리자(2611008) 선택지 5곳, 개발1팀 결재라인 저장

## 7-2. 화면 수정 (2026-11-10 사용자 검토)

- 결재함 탭 순서: 결재 대기 | 결재 예정 | 결재 완료 | 기안함 | 임시저장 | (관리자) 전체 문서 - 결재자 탭 다음 기안자 탭
- **결재선 접기·펼치기** (`StepsDisclosure`, 상세 화면): 평소엔 요약 버튼("결재선 · 3명 중 2명 승인 · 지금 차례: 신현우")만 보인다.
  - 마우스를 올리면 펼침, 버튼·펼친 영역 밖으로 나가면 0.15초 뒤 접힘(옮겨 가는 사이 닫히지 않게)
  - 클릭하면 펼친 채로 고정, 다시 누르거나 바깥을 누르면 접힘 (모바일 터치도 같은 방식)
  - Radix Popover가 바깥 클릭·Esc 닫기를 맡고, 마우스 올리기는 `pointerType === "mouse"`일 때만 연다(터치도 pointerenter가 발생해 구분하지 않으면 누르자마자 열렸다 닫힘). 버튼 클릭은 `preventDefault`로 Radix 기본 토글을 막고 "고정" 상태로 바꾼다(마우스로 이미 열려 있어도 클릭이 닫기가 되지 않게)
  - 확인: 접힘·올리면 펼침·내리면 접힘·클릭 고정·바깥 클릭 접힘, 모바일(터치) 누르면 펼침·바깥 누르면 접힘·버튼 두 번이면 접힘, 390px 넘침 없음
- 결재라인 관리 제목: 전체 관리자만 "공용·부서 결재라인 관리", 부서 관리자는 "부서 결재라인 관리" (공용은 관리할 수 없으므로)

## 8. 설계 포인트
- 버튼 권한을 서버 응답(`permissions`)으로만 결정 → 규칙 중복 없음, 화면 숨김은 편의이고 실제 차단은 서버
- 임시저장·상신 API 분리와 "저장은 됐는데 상신만 실패"한 경우의 처리
- 동시 처리 409를 받으면 다시 조회해 화면을 최신 상태로
- 공용 에디터에 옵션 하나(`allowImages`)만 추가해 게시판 동작을 바꾸지 않고 재사용
