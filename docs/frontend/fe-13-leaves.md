# FE-13 휴가 (전자결재 휴가 신청 · 휴가내역 · 캘린더 휴가자 · 연차 관리)

> 작성일: 2026-11-12
> 업무 규칙은 [features.md 7.4](../design/features.md) "휴가 신청 규칙"·"휴가 화면 구성"과 5.3 "휴가자 표시 옵션", 백엔드 구조·API는 [backend/leaves.md](../backend/leaves.md).
> 화면 구성(신청은 전자결재, 마이페이지 아래 [휴가내역], 캘린더 게시판 옵션)은 사용자 결정, 세부 배치는 Claude가 공통 규칙 안에서 정했다.

## 1. 화면과 경로

| 경로 | 화면 | 누가 |
|---|---|---|
| `/approvals/new?type=leave` | 전자결재 작성에서 문서 유형 **휴가 신청** (휴가 옵션이 켜져 있을 때만 유형 토글이 보임) | 직원 |
| `/approvals/[id]` | 휴가 문서는 본문 대신 **휴가 정보**(유형·단위·기간·일수·사유) | 기안자·결재라인·관리자 |
| `/approvals/[id]/edit` | 휴가 임시저장 수정 (휴가 정보를 불러와 휴가 API로 저장) | 기안자 |
| `/leaves` | **휴가내역**: 연도별 전체 휴가(부여)·사용·결재 중·남은 연차 + 신청 이력, [휴가 신청] | 직원 |
| `/boards/[boardId]` (캘린더) | 게시판 옵션 "휴가자 표시"가 켜져 있으면 날짜마다 **휴가 N명** 항목 하나 | 게시판 읽기 권한자 |
| `/admin/boards` | 게시판 추가·수정: 타입이 캘린더면 "휴가자 표시" 체크박스 | 관리자 |
| `/admin/leaves` | **연차 관리**: 회원별 계산값·조정값·부여·사용·결재 중·잔여, [조정], [지금 재계산] | 관리자 |

- 사이드바: 직원 "개인 > 마이페이지" 아래 **휴가내역**, 관리자 **연차 관리**. 둘 다 `addon: "leaves"`
- `/leaves`, `/admin/leaves`는 레이아웃에서 `<AddonGate name="leaves">` (꺼지면 일반 404)
- 결재 화면·캘린더·게시판 관리는 휴가가 꺼져 있으면 휴가 관련 부분만 숨긴다(문서 유형 토글은 `GET /approvals/document-types`에 `LEAVE`가 있을 때, 체크박스·캘린더 항목은 `useEnabledAddons`)

## 3. 전자결재로 휴가 신청 (API가 둘로 나뉨)

```text
[상신] → POST /approvals/leaves (문서 + 휴가 정보 임시저장, 응답 documentId)
       → PATCH /approvals/documents/:documentId/submit (결재 API 그대로)
       └ 상신만 실패(연차 부족·시간 겹침 등 400) → 임시저장으로 남음 → 수정 화면으로 보내고 오류 안내 (일반 문서와 같은 흐름)
[수정] → PATCH /approvals/leaves/documents/:id (휴가 문서는 결재 문서 수정 API가 400 - 제목을 서버가 만들기 때문)
회수·승인·반려·삭제·다시 기안 → 결재 API 그대로 (다시 기안하면 휴가 정보도 복사돼 수정 화면에 채워짐)
```

- `useSaveAndSubmit`의 저장 함수가 문서 id를 돌려주게 바꿔(휴가는 `documentId`) 일반 문서와 같은 흐름을 쓴다.
- 문서 유형을 URL에 둔 이유: [휴가내역]의 [휴가 신청] 링크로 바로 휴가 작성 화면을 열기 위해서. 유형을 바꾸면 폼을 새로 그린다(`key`).

## 4. 캘린더 "휴가 N명"

- 게시판(핵심)은 휴가를 모르므로 화면이 두 API를 합친다: 일정 응답의 `showLeaves`가 true이고 휴가 애드온이 켜져 있으면 `GET /approvals/leaves/calendar`를 같은 기간으로 부른다. 휴가 조회가 실패해도 일정은 그대로 보인다.
- 칸마다 항목 하나(초록색으로 일정과 구분 - 처음엔 점선·회색이었으나 잘 안 보여 사용자 요청으로 변경). 마우스를 올리면 명단(이름(직급/소속) · "휴가" 또는 시각, 처음엔 소속/직급이었으나 사용자 요청으로 순서 변경), 터치는 눌러서 열고 닫는다. 마우스로 열린 상태에서 누르면 닫히지 않게 Radix 기본 토글을 막는다(FE-12 결재선 접기와 같은 처리).
- 명단은 서버가 최종 승인된 휴가만, 유형 없이 보낸다. 종일 휴가는 **"휴가"**로 표시한다(2026-11-12 사용자 결정 - 유형을 숨기므로 "연차"가 아니라 "휴가").

## 6. 설계 포인트
- **"공통 캘린더가 휴가를 모르는데 어떻게 표시하나요?"** → 게시판은 옵션 값만 저장해 일정 응답에 실어 주고, 화면이 그 값과 애드온 켜짐 여부를 보고 휴가 API를 따로 불러 합친다. 핵심 → 애드온 코드 의존이 없다.
- **"휴가 신청 화면을 따로 만들지 않은 이유는?"** → 결재선·첨부·임시저장·상신 흐름이 전자결재와 같아서, 작성 화면에 문서 유형만 추가하고 저장 API만 갈랐다. 결재 상세·결재함·알림도 그대로 쓴다.
- **"화면에서도 일수를 계산하는데 서버와 다르면요?"** → 화면 계산은 미리보기일 뿐이고 저장·상신 때 서버가 다시 계산·검사한다. 다르면 서버 기준으로 400과 메시지가 온다.

## 7. 추가: 영구 조정 (2026-11-12)

- 연차 관리 표에 **영구 조정 · 올해 조정** 열을 나눠 보여 준다(칸에 마우스를 올리면 사유).
- [조정] 창 입력란 4개(사용자 결정): 영구 조정값·영구 조정 사유 / 매년 초기화되는 조정값(그 연도)·그 연도 조정 사유. 위에 "부여 = 계산값 + 영구 + 그해 조정 = N일"을 입력에 맞춰 바로 계산해 보여 준다.
- 입사한 해 행이면 영구 조정 도움말이 "입사한 해에는 적용되지 않습니다"로 바뀐다(서버와 같은 규칙).
- 값이 0이 아니면 사유 필수(화면·서버 둘 다), 고친 칸의 오류는 입력하면 바로 지운다.
- 휴가내역의 "전체 휴가" 카드 아래에 "영구 조정 +N일 · 올해 조정 +N일"
- 확인(브라우저): 표 열, 입력란 4개, 사유 없으면 오류, 영구 +2 저장 → 부여 22, 0으로 되돌림
