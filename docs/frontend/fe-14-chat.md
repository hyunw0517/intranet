# FE-14 채팅 (헤더 배지 · 떠 있는 창 · 실시간 받기)

> 작성일: 2026-11-13 · 브랜치 `frontend/chat`
> 채팅 규칙(방·메시지·읽음)은 [features.md](../design/features.md) 8장, 백엔드 코드는 `backend/src/chats/`.

## 1. 화면

헤더 오른쪽 **테마 선택 · 알림 · 채팅 · 사용자 메뉴** 순서 (2026-11-13 사용자 결정: 우측 하단 고정 버튼 대신 헤더 도구에 포함).

- 안 읽은 메시지가 있으면 채팅 아이콘에 **빨간 원 + 흰 숫자**(100 이상은 `99+`). 알림의 빨간 점과 구분된다.
- 누르면 **오른쪽 아래에 떠 있는 창**(380px, 최대 높이 640px)이 열린다. 뒤 화면을 덮지 않아 창을 띄운 채로 메뉴를 옮기고 글을 쓸 수 있다. **페이지를 옮겨도 창이 유지된다**(사용자 요구).
  - 창을 닫으면(× 또는 헤더 아이콘) 다음에 열 때 **방 목록부터** 보인다. 보던 방이 그대로 뜨지 않는다(2026-11-13 사용자 요구).
  - **위쪽 줄을 잡고 끌어서 옮길 수 있다**(PC·태블릿, `hooks/use-floating-window.ts`).
  - **가장자리·모서리를 끌어 크기를 바꿀 수 있다**(PC·태블릿, 같은 훅, 2026-11-14 사용자 요청). 최소 320×420px, 최대 너비 720px·높이 화면 높이(가장자리 16px씩 남김), 화면 밖으로 넘어가지 않는다. 브라우저가 줄면 최대에 맞춰 줄인다.
  - **위치·크기는 이 브라우저의 localStorage(`intranet.chat-window`)에 기억**한다(2026-11-14 사용자 결정, 11-13의 "닫으면 원래 자리"를 바꿈). 새로고침·다시 로그인해도 그대로 열고, 저장값이 지금 화면보다 크거나 밖이면 화면 안으로 맞춘다. 다른 브라우저·PC는 기본값. 모바일 폭(화면 전체)에서는 적용하지 않고 저장값도 그대로 둔다.
  - **위쪽 줄을 두 번 누르면** 기본 자리·크기(오른쪽 아래, 380px × 최대 640px)로 돌아가고 저장값을 지운다. (두 번 누르기는 포인터를 창에 묶은 뒤라 이벤트 대상이 창 전체로 오므로, 누를 때 위쪽 줄이었는지 기록해 두고 판단한다)
    - 창 전체가 화면 안에 있도록 제한하고, 브라우저 크기가 바뀌면 다시 맞춘다. 위쪽 줄의 버튼 위에서는 끌기를 시작하지 않는다. 두 번 누르면 원래 자리.
    - 위치는 기본 자리에서 옮긴 거리만 state로 두고 `transform: translate()`로 그린다. 창 안 메뉴·대화상자는 portal로 따로 그려져 위치가 어긋나지 않는다.
  - 오른쪽 위 토스트(`Toaster position="top-right"`)와 겹치지 않도록 아래쪽에 붙였다.
  - 모바일(640px 미만)은 작은 창이 좁아서 화면 전체로 연다.
- 창 안 화면 (위 줄에 뒤로 · 제목 · 닫기)
  - **목록**: 최근 메시지 순. 방 이름 · 그룹 인원 · 마지막 메시지 · 시각 · 방별 안 읽은 수
    - **두 번 눌러야 방이 열린다**(2026-11-13 사용자 결정). 한 번 누르면 선택 표시만 한다. 키보드는 Enter로 연다(버튼의 Enter는 원래 click이라 keydown에서 먼저 받는다). 모바일은 `touch-manipulation`으로 두 번 탭이 확대가 아니라 더블 클릭이 되게 한다.
  - **새 채팅**: 이름·사번·부서로 검색해 체크. 1명이면 1:1, 2명 이상이면 그룹
    - 그룹 이름은 선택이다. 비우면 서버가 참여자(본인 포함) 이름으로 만든다: 영문 → 한글 가나다순, 3명까지 쉼표, 넘으면 "외 N명". 만들 때 한 번만 정하고 이후 참여자가 바뀌어도 그대로다(2026-11-13 사용자 결정, 백엔드 작업 필요)
  - **대화**: 날짜 구분선, 내 메시지는 오른쪽(강조색), 상대 이름은 연속 메시지에서 한 번만, 옆에 안 읽은 사람 수(카톡의 "1")·"수정됨"·시각. 시스템 메시지는 가운데 작은 글씨. [이전 메시지]로 위로 이어 받기
    - 같은 사람이 같은 날 같은 분에 이어 보낸 메시지는 **마지막 메시지에만 시각**을 표시한다(`sameMinuteGroup`, 2026-11-19 사용자 요청). 안 읽은 사람 수·"수정됨"은 메시지마다 그대로. 보낸 사람을 알 수 없거나 사이에 시스템 메시지가 있으면 묶지 않는다
    - 보낸 사람 이름·시스템 메시지·안 읽은 사람 수·"수정됨"·시각은 드래그로 선택되지 않아 복사 내용에 섞이지 않는다(`select-none`, 2026-11-19 사용자 요청)
    - **복사 형식**(`chat-copy.ts`, 2026-11-19 사용자 결정): 메시지마다 `[이름] [오전/오후 h:mm]` 다음 줄에 본문. 같은 사람이 같은 분에 이어 보낸 메시지는 이름·시각을 한 번만 쓰고 본문을 잇는다(사이에 다른 사람 메시지가 있으면 나눈다). 날짜 구분선은 `2026년 11월 13일 금요일` 한 줄, 파일은 `[이미지]`·`[동영상]`·`[파일]`, 삭제는 `[삭제된 메시지]`, 시스템 메시지는 제외. 메시지 하나의 일부만 고르면 고른 글자만 복사하고, 두 건 이상 걸치면 걸친 메시지의 본문 전체를 복사한다
  - 내 메시지(보낸 뒤 5분 이내)에 마우스를 올리면 [⋯] → 수정(그 자리에서) · 삭제(확인 후 "삭제된 메시지입니다")
  - 입력: Enter 보내기, Shift+Enter 줄바꿈. 1:1 상대가 퇴사·비활성이면 입력란 대신 안내 문구
  - 메뉴: 참여자 보기(방장은 내보내기) · 대화 상대 초대(그룹) · 방 이름 변경(그룹 방장) · 나만 보는 이름 · 나가기(그룹 방장은 다음 방장 선택, 기본 자동)
- 승인 전(GUEST)이거나 채팅 애드온이 꺼져 있으면 버튼·창·소켓 연결이 모두 없다.

### 1.1 파일 메시지 (2026-11-13 사용자 결정, 규칙은 features.md 8.4)

- 입력란 왼쪽 [클립] 버튼(여러 개 선택) 또는 대화 영역에 **끌어다 놓기**("여기에 놓으면 보냅니다"). 한 번에 최대 10개, 이미지는 장당 20MB·그 밖의 파일은 200MB, 게시판 첨부와 같은 확장자. 하나라도 걸리면 안내만 하고 보내지 않는다. 읽기 전용 방은 버튼·놓기 모두 없음
- 보내는 동안 클립 자리에 **스피너**, 여러 개면 아래에 **"3/7"**(파일 하나가 끝날 때마다 증가), 끝나면 둘 다 사라진다
- 말풍선
  - 이미지: 묶음 격자(1장 크게 · 2장 2열 · 3장 이상 3열). 썸네일을 받아 그리고, 없거나 못 불러오면 **엑스박스**(밝은 회색 바탕 + 가운데 어두운 회색 X). 누르면 원본 보기 + 내려받기
  - 동영상·파일: 회색 아이콘 + 이름 + 크기 + 다운로드 아이콘. **줄 전체가 내려받기 버튼**(아이콘·이름 어디를 눌러도, 손가락 커서), 글자는 드래그로 선택되지 않음 (2026-11-14 사용자 요청)
    - **모든 파일**(이미지 포함)은 받기 전에 확인 창 `"파일명.확장자" 파일을 다운로드 받으시겠습니까?` + 보안 경고(주황 박스 + 경고 아이콘: "출처를 알 수 없는 파일은 악성 코드가 포함되어 있을 수 있습니다." - 시설 사용 불가 기간 창의 경고 박스와 같은 모양). 게시판 첨부와 같은 공용 컴포넌트 `components/common/file-download-confirm-dialog.tsx` → [다운로드] / [취소] (줄·보관함 칸·이미지 원본 보기의 [내려받기] 모두, 2026-11-14 사용자 요청 - 보안 차원). 이미지도 묻는 이유: 확장자만 이미지인 가짜 파일도 "이미지"로 분류되어, 빼면 그 파일은 묻지 않고 받아진다. 확인 창은 누르는 버튼 바깥에 그린다(안에 두면 React 이벤트가 바깥 버튼까지 올라가 창이 다시 열림)
  - 내 파일 메시지(5분 이내) 메뉴에는 **삭제만**(묶음은 통째로)
- 목록 미리보기: 회색 작은 아이콘 + "이미지" / "동영상" / "파일명.확장자"
- 파일 아이콘: 동영상 = 비디오, 압축(`.zip`) = 지퍼 달린 폴더(`FolderArchive`), 그 밖의 파일 = 파일 (`FileKindIcon`)
- **파일 보관함**: 방 메뉴 → [파일 보관함] ("대화 상대 초대"와 "방 이름 변경" 사이, 위아래 구분선). 최신순 3열 격자, 이미지는 미리보기(누르면 원본 보기), 그 밖의 파일은 아이콘 + 이름 · 크기 + 오른쪽 위 다운로드 아이콘이고 **칸 전체가 내려받기 버튼**(글자 드래그 안 됨). [더 보기]로 이어 받기, 열어 둔 채 파일이 오거나 지워지면 바로 반영

## 3. 데이터 흐름

```text
보내기·수정·삭제·방 관리·읽음 ── REST ──▶ /api/chats/* ──▶ NestJS (트랜잭션 커밋)
                                                              │ 커밋 후 푸시
받기 ◀── Socket.IO (/api/socket.io, user:{id} room) ◀──────────┘
   └─ use-chat-socket → TanStack Query 캐시 → 화면
```

- **소켓은 받기만 한다**(features.md 8.1). 보낸 메시지는 REST 응답으로 바로 캐시에 넣고, 같은 메시지가 소켓으로 다시 와도 id로 걸러 한 번만 보인다.
- 푸시 처리 방식은 둘로 나눴다.
  - **열어 둔 대화**(`message:created/updated/deleted`, `room:read`): 캐시를 직접 고친다. 다시 받으면 대화가 깜빡이고 스크롤이 튄다.
  - **목록·배지**: 서버 값으로 다시 받는다(무효화). 안 읽은 수 규칙(내 메시지·시스템·삭제 제외, 참여 시점 이후)을 화면에서 따라 하면 서버와 어긋나기 쉽다.
- **읽음**: 대화를 보고 있으면 가장 최신 메시지 id로 `POST /chats/:id/read` → 서버가 `room:read` 푸시 → 다른 참여자 화면의 "1"이 줄고 내 배지가 갱신된다.
- **메시지별 안 읽은 사람 수**: 방 상세의 참여자별 `lastReadMessageId`·`joinedAt`으로 화면이 계산한다(`unreadReaders`).
- **파일 보내기**: 요청 1개 = 메시지 1개. 이미지는 한 요청으로 묶어 `POST /chats/:roomId/images`, 동영상·파일은 하나씩 `POST /chats/:roomId/files`로 차례로 보낸다(서버가 경로별로 용량 한도를 건다). 묶음 요청 안의 "끝난 파일 수"는 보낸 바이트가 앞 파일들의 크기 합을 넘을 때마다 세고, 마지막 파일은 서버 응답이 와야 끝난 것으로 본다(`filesSent`). 실패한 요청만 안내하고 나머지는 계속 보낸다.
- **썸네일·원본·다운로드**: Bearer 헤더가 필요해 `<img src>`·`<a href>`를 바로 쓰지 못한다 → Blob으로 받아 `blob:` 주소로 그리고, 화면에서 사라지면 해제한다.

### 창이 페이지를 옮겨도 남는 이유

`ChatProvider`를 루트(`AppProviders`)에 둔다. App Router는 페이지를 옮길 때 바뀐 부분만 다시 그리고 위쪽 레이아웃·Provider는 그대로 두므로, 열린 방·입력 중인 글·소켓 연결이 남는다. `(main)`·`admin` 레이아웃에 두면 두 영역 사이를 옮길 때 레이아웃이 바뀌어 사라진다.

### 소켓 연결이 끊기는 경우

| 경우 | 처리 |
|---|---|
| access token 만료 시각에 서버가 끊음 (`io server disconnect`) | 재발급(`refreshAccessToken`) 후 다시 연결 |
| 인증 실패 (`connect_error`, `socket.active === false`) | 재발급 후 다시 연결, 연속 3번 실패하면 멈춤 (socket.io는 미들웨어 거절이면 스스로 다시 연결하지 않는다) |
| 네트워크 끊김 | socket.io가 스스로 다시 연결. `auth`를 함수로 넘겨 그때의 최신 토큰을 쓴다 |
| 다시 연결됨 | 끊긴 동안 놓친 푸시가 있을 수 있어 채팅 캐시(`chatKeys.all`)를 모두 새로 받는다 |

## 4. 시행착오: 소켓 주소의 끝 슬래시

- Socket.IO 서버 주소는 `/socket.io/`(끝 슬래시)여야 한다. 슬래시가 없으면 NestJS가 404를 낸다.
- 그런데 Next는 끝 슬래시 주소(`/api/socket.io/`)를 **308로 슬래시 없는 주소로 바꾼다**. 그래서 기존 `/api/:path*` rewrite만으로는 연결이 안 됐다(curl로 308 → 404 확인).
- 해결: 클라이언트가 슬래시 없이 요청하고(`addTrailingSlash: false`), `next.config`에 `/api/socket.io` → `${API_SERVER_URL}/socket.io/` rewrite를 따로 둔다. 쿼리(`?EIO=4&transport=...`)는 그대로 전달된다.
- Next 전체 설정 `skipTrailingSlashRedirect`는 다른 페이지 주소에도 영향을 줘서 쓰지 않았다.
- 운영은 Nginx가 `/api`를 떼고 전달하므로 같은 규칙(슬래시를 붙이거나 그대로 전달 + WebSocket upgrade 헤더)을 배포 때 맞춘다(`need_list.md`(비공개) 2장).

## 6. 설계 포인트
- 소켓은 받기만 하고 보내기는 REST로 한 이유 (기존 가드·DTO 검증·트랜잭션 재사용, 커밋 후 푸시)
- 푸시를 캐시에 반영하는 두 방식(직접 수정 vs 무효화)과 고른 기준
- 보내기 응답과 소켓 푸시가 둘 다 오는 중복을 id로 거르기
- 토큰 만료 시 서버가 끊고 클라이언트가 재발급 후 다시 연결하는 흐름, `auth`를 함수로 넘기는 이유
- 한글 입력 중 Enter(`isComposing`) 처리 - 안 막으면 마지막 글자가 한 번 더 보내진다
- 창을 루트 Provider에 둬서 페이지 이동에도 유지되는 이유 (App Router 레이아웃 유지)
